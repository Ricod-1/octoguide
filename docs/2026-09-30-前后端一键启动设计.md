# OctoGuide 一键启动（前后端）设计

日期：2026-09-30
状态：已实现；通过 DryRun、停止空跑、AST 语法、ASCII 检查与快捷方式读回验证

## 目标

提供一个双击即可启动 OctoGuide 前后端的入口，并在启动后让用户能持续看到后端日志。

## 现状

- 项目根目录已有两个独立脚本：`start-backend.cmd`（设置 JAVA_HOME 后 `mvn spring-boot:run`）与
  `start-frontend.cmd`（进入 `frontend` 后 `npm run dev`），各自需要手动双击。
- 后端 8080、前端 5173；MySQL 以名为 `MySQL` 的 Windows 服务运行。
- 项目路径与 Node 安装路径含中文，脚本需正确处理编码。
- 仓库尚无 git，spec 暂不提交。

## 方案选择

| 方案 | 说明 | 结论 |
| --- | --- | --- |
| A 纯 cmd 编排 | 全部逻辑写在 `start-all.cmd` | 内联 PowerShell 转义复杂，中文路径易出错 |
| **B cmd 入口 + PS 编排** | `start-all.cmd` 极薄，逻辑在 `start-all.ps1` | **采用**：中文路径、端口探测、错误处理都干净 |
| C Windows Terminal 多标签 | 依赖 `wt.exe` | 依赖外部组件，放弃 |

## 组件

新增 3 个文件，均放在项目根目录；**不修改**现有 `start-backend.cmd` / `start-frontend.cmd`。

1. `start-all.cmd`（双击入口，纯 ASCII）
   - `chcp 65001` → `powershell -NoProfile -ExecutionPolicy Bypass -File start-all.ps1`
   - 把命令行参数原样透传（便于 `-DryRun` / `-NoPause`）
2. `start-all.ps1`（全部编排逻辑，UTF-8 **带 BOM**，供 Windows PowerShell 5.1 正确读取中文）
   - 模式：默认启动；`-DryRun` 只打印计划不拉起进程；`-Stop` 停止；`-NoPause` 结束后不等按键
   - 顶部集中声明可配置项：`JAVA_HOME`、Maven 路径、MySQL 服务名、两个端口、就绪超时（默认 180s）
3. `stop-all.cmd`（纯 ASCII）：调用 `start-all.ps1 -Stop`

桌面快捷方式：`OctoGuide 一键启动.lnk`
- 目标 `start-all.cmd`，工作目录 = 项目根，图标取 `shell32.dll` 内置图标
- 不设置全局热键（按用户确认）

## 启动流程（默认模式）

1. 前置检查：`JAVA_HOME` 目录、`mvn.cmd`、`npm.cmd` 是否存在；缺失则红字报错并暂停退出
2. MySQL：`Get-Service MySQL`；未运行则 `Start-Service`。失败（通常为权限不足）只告警并提示
   `net start MySQL`，**不中断**启动流程，真实错误留给后端窗口暴露
3. 端口幂等：8080 / 5173 已在监听则跳过对应启动，汇总中标注“已运行（跳过启动）”
4. 后端：`Start-Process start-backend.cmd` 开**独立窗口**，该窗口即后端实时日志窗口，
   标题为脚本内 `title OctoGuide Backend (8080)`
5. 就绪等待：轮询 TCP 8080（上限 180s，覆盖 Maven 首次启动），随后请求 `GET /api/status`
   确认 HTTP 可用；超时不杀进程，只提示“仍在启动中，请查看后端窗口”
6. 前端：`Start-Process start-frontend.cmd` 开独立窗口
7. 汇总：启动器窗口打印后端/前端状态与日志窗口名，按回车关闭
   （`-NoPause` 用于自动化调用，跳过该等待）

不自动打开浏览器（按用户确认）。

## 停止流程（`-Stop`）

1. 结束监听 8080 / 5173 的进程（`Get-NetTCPConnection`，缺失时回退解析 `netstat -ano`）
2. 兜底清理命令行中含项目根路径且匹配 `spring-boot:run` / `vite` 的残留进程（Maven / Node 包装进程）
3. 打印实际结束的 PID 列表；无匹配时明确提示“没有正在运行的实例”，退出码 0

停止模式不执行 Java/Maven/Node/MySQL 前置检查（即使工具链缺失也应能停止进程）。

## 数据流与边界

- 启动器只负责“编排进程”，不注入任何应用配置；后端仍按 `application-local.yml` 与
  `spring.profiles.default=local` 运行，行为与手动双击 `start-backend.cmd` 完全一致
- 两个子窗口相互独立：任一崩溃不影响另一个，日志互不干扰
- 幂等：重复双击不会重复拉起 Maven/Node，避免端口冲突

## 错误处理

| 场景 | 行为 |
| --- | --- |
| Java/Maven/Node 缺失 | 红字说明缺哪个、期望路径，暂停后退出（退出码 1） |
| MySQL 未运行且无权限启动 | 告警 + 提示手动命令，继续启动 |
| 后端 180s 未就绪 | 告警 + 提示查看后端窗口，继续启动前端 |
| 端口已被占用 | 跳过启动并标注，不报错 |
| 停止时无进程 | 明确提示，退出码 0 |

## 验证方式

不拉起真实服务（不占用 8080/5173）：

1. `.ps1` 通过 PowerShell AST 解析校验；确认带 BOM、能正确显示中文
2. `.cmd` 仅含 ASCII，避免 `chcp` 生效前的乱码
3. `start-all.ps1 -DryRun -NoPause`：打印完整计划且不产生新进程，8080/5173 仍空闲
4. `start-all.ps1 -Stop -NoPause`：无实例时提示“没有正在运行的实例”，退出码 0
5. 读回桌面 `.lnk` 的 `TargetPath` / `WorkingDirectory` 确认指向正确

真实端到端启动（占端口 1–2 分钟）不在本次范围内，按用户确认跳过。

## 不在范围内（YAGNI）

- 不自动打开浏览器、不设置全局热键
- 不改动现有两个启动脚本的行为
- 不做 Windows 服务化、不做 CI/部署脚本
- 不引入日志文件落盘（后端窗口即日志视图）
